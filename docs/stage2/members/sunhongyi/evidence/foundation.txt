三、过程中发现的两个真问题（都已处理并需告知相关人）
====================================================================
问题1 capture 包不被扫描
  现象：首轮启动后 POST /api/v1/dev/spawns 返回 404 "No static resource"。
  原因：@SpringBootApplication 在 edu.pkmon.demo.PkmonApplication，组件扫描范围只有
    edu.pkmon.demo，不包含 edu.pkmon.capture。启动类主责是胡豪，本模块不能改。
  处理：本模块以 Spring Boot 自动配置注册自己（CaptureConfig + AutoConfiguration.imports），
    所有 @Bean 都带 @ConditionalOnMissingBean。若日后启动类改为扫描 edu.pkmon，
    本模块的 @Bean 会自动让位，不会重复定义。
  建议：由胡豪决定是改扫描范围（更省事）还是保留自动配置；两条路都已可用。

问题2 旧 DemoController 与新接口路径冲突
  现象：旧 DemoController 也映射 POST /api/v1/capture/challenge 与 /api/v1/capture/answer，
    两个控制器同时注册会构成歧义映射，启动即失败。
  处理：把旧演示的两个路由迁到 /api/v1/demo/capture/challenge 与
    /api/v1/demo/capture/answer，其余旧路由（/api/v1/demo/sessions、state、explore、reset）不变。
    迁移后旧流程实测仍 200，未被破坏。
  影响：客户端若直接调用旧路径，需改这两处（属冉昕霖网络层，已记入 questions.csv Q10）。

  存储：repository/memory/ 下的实现是内存替身，进程重启即丢失。
