====================================================================
本阶段优先分析“答题捕获与精灵收录”这一项核心功能的业务模型、状态与事务语义，
不把 Controller、数据库表、索引塞进分析类图；技术对象留到 design 阶段。

范围说明：
- 开发遭遇（dev spawn）在本阶段明确是模拟来源，不是真实定位结果。
- 新题库、战斗、复杂奖励概率后置，本阶段不分析。
- 分析对象以本指南统一名称为准：Spawn、Challenge、Question、AnswerAttempt、
  CaptureRecord、SpawnService、CaptureService、CollectionService。

2. 正常流程与异常流程
====================================================================
2.1 正常答对
    待填（须写清：捕获成功在哪一步真正发生、以什么为界）

2.2 答错后重试
    待填（须写清：挑战是否仍为 OPEN、是否产生 CaptureRecord、能否重新作答）

2.3 无效选项
    待填（须写清：是否消耗挑战、是否记入 AnswerAttempt）

2.4 挑战过期
    待填（须写清：过期边界判定依据、过期后作答的返回、过期后能否读取原结果）

2.5 重复请求
    待填（须区分：同 requestId 同内容 = 返回原结果；
          同 requestId 不同内容 = 冲突且不改原记录；
          不同 requestId 重复作答 = 业务重试）
    统一约束：HTTP 成功不等于捕获成功，判定以业务 code 与实际 CaptureRecord 为准。

2.6 访问他人资源
    待填（须写清：他人 challengeId / captureRecordId 的返回，且不泄露所属用户）
